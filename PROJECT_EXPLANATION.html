이 프로젝트가 뭔가요?

유튜브, 틱톡, 인스타 릴스… 우리가 매일 보는 영상의 대부분은 추천 알고리즘이 골라준 것입니다.

그런데 이런 의문이 들 수 있어요:

"추천 알고리즘이 정말 효과가 있는 걸까?"

"혹시 내가 보고 싶은 것만 보여줘서 세상이 좁아지는 건 아닐까?"

이 프로젝트는 중국의 숏폼 영상 플랫폼 Kuaishou(쾌수)의 실제 데이터를 가지고, 이 두 가지 질문에 숫자로 답합니다.

추천 알고리즘은 클릭률을 153% 올리지만,
전체 유저의 92.4%에서 콘텐츠 다양성을 떨어뜨린다.

쉽게 말하면: "효과는 확실하지만, 부작용도 확실하다."

어떤 데이터를 썼나요?

두 종류의 데이터를 사용했습니다.

덕분에 "이 유저가 이 영상을 봤다면 좋아했을까?"를 확인할 수 있습니다.

분석 순서 한눈에 보기

① 데이터 탐색 — 데이터가 어떻게 생겼는지 파악
② A/B 테스트 — 추천이 효과가 있는지 "비교"
③ 인과추론 — 정말 추천 때문인지 "증명"
④ 오프라인 평가 — 새 알고리즘을 미리 "예측"
⑤ 필터버블 분석 — 추천의 "부작용" 측정
⑥ 종합 리포트 — 비즈니스 제안으로 정리

각 단계를 하나씩 풀어보겠습니다.

Step 1 데이터 탐색 — 일단 눈으로 보자

분석 전에 데이터의 전체 모습을 파악한 단계입니다.

확인한 것들:

  • 유저가 영상에 보이는 반응은 12가지 (클릭, 좋아요, 싫어요, 댓글, 팔로우, 공유 등)
  • 유저마다 활동량이 천차만별 (하루 1개 보는 사람 vs 100개 보는 사람)
  • 추천 영상은 랜덤 영상보다 모든 참여 지표가 높음

왜 이걸 하나요?
요리 전에 재료를 확인하는 것과 같습니다. 데이터에 빈 값은 없는지, 이상한 값은 없는지, 전체적인 패턴은 어떤지 먼저 봐야 나중에 분석이 엉뚱한 방향으로 가지 않습니다.

Step 2 A/B 테스트 — 추천 vs 랜덤, 뭐가 나아?

질문: 추천 ON vs OFF, 유저 반응이 달라질까?

A/B 테스트란?
두 그룹을 만들어서 하나(A)에는 기존 방식, 다른 하나(B)에는 새 방식을 적용한 뒤 결과를 비교하는 실험.
신약 임상시험에서 진짜 약 vs 위약(플라시보)을 비교하는 것과 같은 원리입니다.

결과

지표랜덤 노출추천 노출변화해석
클릭률(CTR)17.6%44.5%+153%추천 영상을 2.5배 더 많이 클릭
좋아요0.5%1.8%+269%좋아요를 3.7배 더 많이 누름
팔로우0.03%0.13%+410%크리에이터 팔로우가 5배 증가
댓글0.03%0.25%+610%댓글 작성이 7배 증가
싫어요0.11%0.08%-32%싫어요는 오히려 감소

이게 우연이 아니라는 걸 어떻게 알아?

쉽게 설명하면:

동전을 10번 던져서 앞면이 7번 나왔다면, "이 동전이 특별한 건지" 아니면 "운이 좋았던 건지" 헷갈리죠.
하지만 10,000번 던져서 7,000번 앞면이 나왔다면? 이건 운이 아니라 진짜 뭔가 다른 것입니다.

p-value(피벨류)가 그 "운일 확률"인데, 이 분석에서는 p < 1e-300.
이건 "우연일 확률이 0.000…(0이 300개)…1%"라는 뜻.
즉, 100% 확실하게 추천이 효과가 있다고 볼 수 있습니다.

추가 확인 사항:

  • 효과 크기(Cohen's d) = 0.578 → "중간~큰 효과" (단순히 유의할 뿐 아니라 실질적으로 의미 있는 차이)
  • SRM 검정: 실험 설계에 편향이 없었는지 확인 → 문제 없음
  • Power = 100%: 데이터가 충분해서 작은 차이도 놓치지 않음

Step 3 인과추론 — "정말 추천 때문에" 좋아진 건 맞아?

왜 A/B 테스트만으로는 부족할까?

A/B 테스트에서 "추천 그룹이 더 좋다"는 걸 확인했지만, 한 가지 의문이 남습니다:

"혹시 추천을 많이 받는 유저가 원래 활동적인 사람들이라서 결과가 좋은 게 아닐까?"

이런 문제를 선택 편향(Selection Bias)이라고 합니다.

비유: 헬스장 회원이 비회원보다 건강하다고 해서 "헬스장이 건강하게 만든다"고 단정할 수 없죠.
원래 건강에 관심 있는 사람이 헬스장에 가는 것일 수 있으니까요.

해결 방법: PSM (Propensity Score Matching)

추천을 받은 유저와 "비슷한 조건인데 추천을 안 받은 유저"를 1:1로 짝지어 비교합니다.

비유: 키, 몸무게, 나이, 운동 습관이 비슷한 두 사람 중 한 명만 헬스장에 보내고 결과를 비교.
이러면 "헬스장 효과"만 깔끔하게 뽑아낼 수 있습니다.

ATT = 0.263
추천을 받은 유저는, 안 받았을 때보다 클릭률이 26.3%p 더 높다.
이건 "진짜 추천 때문에" 생긴 효과.

유저마다 효과가 다르다 — CATE 분석 (DR-Learner)

모든 유저에게 효과가 똑같을까? 아닙니다.

DR-Learner란?
단순히 모델 예측값으로만 효과를 추정하는 T-Learner와 달리, 실제 관측값으로 모델 오차를 보정하는 이중강건(Doubly Robust) 방식입니다.
"모델이 틀려도 실제 관측값이 보정해준다" → 더 정확한 개인별 효과 추정.

핵심 인사이트: 모든 유저에게 같은 강도로 추천하는 건 비효율적.
유저 타입에 따라 전략을 다르게 가져가야 합니다.

Step 4 오프라인 정책 평가 — 새 알고리즘을 실험 없이 테스트

문제: 새 알고리즘을 바로 서비스에 올려도 될까?

실제 서비스에 바로 적용하면 안 좋은 알고리즘일 때 유저가 이탈할 수 있고, A/B 테스트를 하려면 시간과 비용이 많이 듭니다.

그래서 이미 있는 데이터로 "미리 시뮬레이션"하는 기술이 필요합니다.

비유: 자동차를 실제 도로에서 테스트하기 전에, 시뮬레이터에서 먼저 돌려보는 것.

어떻게 동작하나? — 핵심 아이디어

예시:

기존 로그: "유저 A가 조회수 기반 추천에서 영상 1, 2, 3을 봤음"

새 알고리즘에게 질문: "유저 A한테 뭘 추천할 거야?" → "영상 2, 4, 5 추천"

기존 로그에서 확인:

  • 영상 2는 실제로 봤음 (클릭 1) ✅
  • 영상 4는 기존 알고리즘이 안 보여줬으니 모름 → DM/SNIPS로 추정
  • 영상 5는 기존 알고리즘이 안 보여줬으니 모름 → DM/SNIPS로 추정

→ 새 알고리즘 예상 성능 = 추정값

3가지 시뮬레이션 방법을 비교

SNIPSIPS의 가중치를 안정화시킨 개선 버전오차 ~10% (실용적)

실제 서비스 투입 전에 "이 알고리즘 쓸 만한가?"를 데이터로 검증할 수 있다는 뜻.

Step 5 필터버블 — 추천이 세상을 좁힌다

필터버블이란?

추천 알고리즘이 "내가 좋아할 만한 것"만 계속 보여주다 보면, 결국 비슷한 콘텐츠만 반복적으로 보게 되는 현상.

유튜브에서 고양이 영상 하나 봤더니 피드가 전부 고양이로 도배되는 경험, 해보셨죠?

어떻게 측정했나?

같은 유저가 랜덤 추천을 받았을 때 vs 알고리즘 추천을 받았을 때 얼마나 다양한 영상을 보게 되는지 비교했습니다.

80% 커버리지가 뭐냐면:
"전체 시청의 80%를 채우려면 영상 몇 개가 필요한가?"라는 질문입니다.

• 랜덤: 전체 영상의 75%가 필요 → 다양하게 분산
• 추천: 전체 영상의 23%만으로 충분 → 소수 영상에 극단적으로 집중

전체 유저의 92.4%에서
추천을 받았을 때 콘텐츠 다양성이 감소했다.

이건 "일부 유저"가 아니라 거의 모든 유저에게 일어나는 구조적 현상입니다.

제안 2: 필터버블 방지 장치

  • 카테고리 쿼터제: 추천 목록에 최소 N개의 서로 다른 카테고리 포함
  • Long Tail 부스팅: 인기 영상뿐 아니라 묻힌 좋은 영상도 일정 비율 추천
  • 탐색 비율 차등 적용: 다양성이 낮은 유저에게 랜덤 추천 비율을 높임

제안 3: 새 알고리즘 사전 검증 프로세스

  • 새 추천 로직을 만들면, A/B 테스트 전에 DM 방식으로 오프라인 시뮬레이션
  • 시뮬레이션 통과한 것만 실제 실험 → 비용과 리스크 절감
  • 정기적으로 소규모 랜덤 실험을 유지해서 평가 데이터 확보

모든 분석에는 한계가 있습니다. 이 프로젝트의 아쉬운 점을 솔직하게 정리합니다.

한계내용개선 방향
실험 설계 동일 유저가 랜덤/추천을 번갈아 경험 → 앞서 본 영상이 뒤 반응에 영향 가능 (순서 효과) Clustered Standard Error, Mixed Effects Model 적용
단기 데이터 17일간 데이터 → 장기적 필터버블 심화 여부 불확실 KuaiRand 전체 4개월 데이터 분석
태그 익명화 영상 카테고리가 숫자 ID만 제공 → "어떤 장르"가 집중되는지 해석 불가 실제 서비스 내부 데이터 활용 시 해결 가능
SHAP 미적용 Feature Importance는 변수의 방향(긍정/부정)을 알려주지 않음 SHAP 값 추가로 방향까지 명확히 제시
플랫폼 특수성 Kuaishou 숏폼 결과를 유튜브, 넷플릭스 등에 그대로 적용하기 어려움 다중 플랫폼 비교 연구
OPE 샘플 200명 샘플로 OPE 수행 → 전체 유저 대비 대표성 한계 전체 유저 + Doubly Robust 추정량 추가

그럼에도 불구하고:
한계를 인식하면서도 공개 데이터만으로 EDA → A/B → 인과추론 → OPE → 필터버블까지 일관된 파이프라인을 구성했다는 점, 그리고 각 분석이 다음 분석의 근거가 되는 인과적 스토리라인을 갖췄다는 점에서 의미 있는 프로젝트입니다.

용어 사전

분석에서 등장하는 용어들을 일상 언어로 풀어놓았습니다.

A/B 테스트
두 그룹을 비교하는 실험 (신약 vs 위약 같은 것)
p-value
"이 결과가 우연일 확률". 낮을수록 결과가 확실함
통계적 유의성
"우연이 아니다"라고 판단할 수 있는 수준 (보통 p < 0.05)
Cohen's d
효과의 실질적 크기. 0.2 작음, 0.5 중간, 0.8 큼
CTR
Click-Through Rate. 영상을 보여줬을 때 클릭하는 비율
PSM
비슷한 조건의 사람끼리 짝지어 비교하는 방법
ATT
실제로 추천 받은 사람들에게 나타난 평균 효과
CATE
유저 개인별로 추정한 추천 효과 (사람마다 다름)
Uplift
"추천했을 때 vs 안 했을 때" 행동 변화량
OPE
기존 데이터로 새 알고리즘 성능을 미리 예측하는 기술
DM / IPS / SNIPS
OPE의 3가지 계산 방식 (각각 정확도와 안정성이 다름)
Shannon Entropy
다양성을 숫자로 나타낸 것. 높을수록 다양함
Gini Index
쏠림 정도. 1에 가까울수록 소수에 집중됨
필터버블
추천이 비슷한 것만 보여줘서 시야가 좁아지는 현상
Long Tail
인기 없지만 가치 있는 콘텐츠들 (전체의 대다수)
